Poll API Reference (Enhanced)
==============================

Summary
-------
The Poll API allows users to create, vote on, view results for, and close different types of polls.
Polls can be of type Yes/No, Rating (1-5), Multiple Choice, or Ranking.

ENHANCEMENT: All polls now support an optional "context" field that provides additional information
about the poll. This context is used by the AI Chat system for better semantic search and responses.

Features:
- Users can create polls of various types with optional context
- Users can cast votes on active polls (with location verification)
- Users can view their own votes, including detailed ranking votes for Ranking polls
- Users can retrieve poll results, which vary depending on poll type
- Users can close polls to prevent further voting
- Users can delete their own votes if they wish to retract them
- All poll data is stored and managed through PollService and PollRepository
- Location validation ensures votes are cast only by users within the defined campus area
- Ranking polls support multi-vote submissions with exact ranking order
- Context field enables AI-powered poll discovery and semantic search
- Polls can be set to PUBLIC (viewable by all) or PRIVATE (viewable/votable only by members/owner).
- Role-based access control: Owners, Moderators, Members
- Moderators can edit polls, view results, and manage access
- Owners can delete polls, assign/revoke moderators, rotate access codes

Base Path: /polls

1. Create Yes/No Poll
POST /polls/yesno

Request Body (JSON):
{
  "title": "Do you like coffee?",
  "context": "This poll is being conducted by the Student Union to determine whether we should extend the hours of the campus coffee shop. We're gathering data on daily coffee consumption habits among students, faculty, and staff. The results will directly influence our decision to keep the coffee shop open until midnight during finals week. Your participation helps us better serve the campus community's needs and preferences regarding caffeinated beverage availability.",
  "emailId": "owner@example.com",
  "visibility": "PUBLIC",
   "moderators": [
       { "moderatorEmail": "mod@campus.edu",
          "duration": "2w" }
     ]
}

Response (JSON):
{
  "id": 1,
  "title": "Do you like coffee?",
  "type": "YES_NO",
  "context": "This poll is being conducted by the Student Union to determine whether we should extend the hours of the campus coffee shop. We're gathering data on daily coffee consumption habits among students, faculty, and staff. The results will directly influence our decision to keep the coffee shop open until midnight during finals week. Your participation helps us better serve the campus community's needs and preferences regarding caffeinated beverage availability.",
  "active": true
  "visibility": "PUBLIC",
    "creatorEmail": "owner@example.com",
    "accessCode": null
}

Note:
- context field is optional
- **emailId** (String, required) is the user creating the poll.
- **visibility** (String, optional, default "PUBLIC") must be "PUBLIC" or "PRIVATE".
- For PRIVATE polls, an **accessCode** will be generated and emailed to the owner.

5. Get All Polls
GET /polls

Query Parameters:
- **emailId** (String, optional): The user's email ID.

Response (JSON):
[
  {
    "id": 1,
    "title": "Do you like coffee?",
    "type": "YES_NO",
    "context": "...",
    "active": true,
    "visibility": "PUBLIC"
  },
  ...
]

Note:
- If emailId is provided, returns all PUBLIC polls + all PRIVATE polls the user is a member of (including owner).
- If emailId is not provided, returns only PUBLIC polls.

6. Get Poll by ID
GET /polls/{id}

Path Variables:
- **id** (Long, required): Poll ID.

Query Parameters:
- **emailId** (String, optional): The user's email ID. Required if the poll is PRIVATE.

Response (JSON):
{
  "id": 1,
  "title": "Do you like coffee?",
  ...
}
OR
{"error": "Access denied. Not a member of this poll."}

Note:
- For PRIVATE polls, the request must include the emailId, and the user must be a member or the owner.

7. Cast a Vote (Yes/No, Rating, Multiple Choice)
POST /polls/{pollId}/vote

Path Variables:
- **pollId** (Long, required): Poll ID.

Query Parameters:
- **userId** (String, required): The voter's email ID.
- **numericValue** (Integer, optional): For YES/NO (e.g., 1/0) or RATING.
- **choice** (String, optional): For MULTIPLE_CHOICE.

Request Body (JSON):
{
  "lat": 40.7128,
  "lng": -74.0060
}

Response (JSON):
{"message": "Vote added"}
OR
{"error": "..."}

Note:
- User must provide **either** `numericValue` or `choice` as a query parameter.
- For PRIVATE polls, user must be a member or the owner to vote.

----------------------------------------------------
8. Submit Ranking Votes (Ranking Polls Only)
POST /polls/{pollId}/vote/ranking

Path Variables:
- **pollId** (Long, required): Poll ID.

Query Parameters:
- **userId** (String, required): The voter's email ID.

Request Body (JSON):
[
  { "choice": "Apple", "rank": 1, "lat": 40.7128, "lng": -74.0060 },
  { "choice": "Banana", "rank": 2, "lat": 40.7128, "lng": -74.0060 },
  { "choice": "Orange", "rank": 3, "lat": 40.7128, "lng": -74.0060 }
]

Response (JSON):
{"message": "Ranking submitted"}
OR
{"error": "..."}

Note:
- All options must be ranked exactly once (ranks 1 to N).
- Location data (lat, lng) is required in at least the first VoteRequest entry for verification.
- For **PRIVATE** polls, user must be a member or the owner to vote.

9. Get User's Vote
GET /polls/{pollId}/user/{userId}

Path Variables:
- **pollId** (Long, required): Poll ID.
- **userId** (String, required): The user's email ID.

Response (JSON) - Non-Ranking Polls:
{
  "id": 101,
  "userId": "user@example.com",
  "choice": "Yes",
  "numericValue": 1,
  "rank": null
}

Response (JSON) - Ranking Polls:
{
  "pollId": 4,
  "userId": "user@example.com",
  "ranking": [
    { "choice": "Apple", "rank": 1 },
    { "choice": "Banana", "rank": 2 }
  ]
}

Response (JSON) - Not Voted:
{"message": "User has not voted on this poll yet."}

GET /polls/{pollId}/results

Path Variables:
- **pollId** (Long, required): Poll ID.

Query Parameters:
- **emailId** (String, optional): The user's email ID. **Required** if the poll is PRIVATE. <-- NEW: Access check parameter

Response (JSON) - RANKING (Borda Count/Scoring Method): <-- NEW: Ranking results structure added
{
  "totalVotes": 5,
  "scores": [
    { "choice": "Apple", "score": 25 },
    { "choice": "Banana", "score": 10 },

11. Close Poll
PUT /polls/{pollId}/close

Path Variables:
- **pollId** (Long, required): Poll ID.

Response (JSON):
{"message": "poll closed"}

Note:
- Sets the poll's 'active' status to **false**, preventing further votes.
- Triggers a live results broadcast.

----------------------------------------------------
12. Delete User's Vote
DELETE /polls/{pollId}/user/{userId}

Path Variables:
- **pollId** (Long, required): Poll ID.
- **userId** (String, required): The voter's email ID.

Response (JSON):
{"message": "Vote deleted"}
OR
{"error": "Vote not found"}

Note:
- Deletes vote(s) for the specified user, including all associated ranking votes.
- Triggers a live results broadcast.

ENHANCEMENTS SUMMARY
----------------------------------------------------

Context Field:
- All poll types now support an optional "context" field
- Context provides additional information about the poll's purpose
- Context is included in semantic embeddings for AI search
- Context appears in poll listings and AI chat responses
- Context field can be null if not provided during creation

AI Integration:
- All polls are automatically embedded when created
- Embeddings use sentence-transformers/all-MiniLM-L6-v2 model
- 384-dimensional vectors stored as JSON in database
- Context field included in text representation for embedding
- Enables semantic search through Chat API

Text Representation for Embedding:
The system generates text representations including:
- Poll ID
- Title
- Type (YES_NO, RATING, MULTIPLE_CHOICE, RANKING)
- Active status
- Options (for Multiple Choice and Ranking polls)
- Context (if provided)

Example:
"Poll ID: 5, Title: "What's your favorite color?", Type: MULTIPLE_CHOICE,
Active: true, Options: [Red, Blue, Green], Context: Logo design survey"

Live Results Broadcasting:
- Vote submissions trigger live result updates via WebSocket
- Poll closure triggers status update broadcast
- Vote deletions trigger result recalculation broadcast
- See LiveResults API documentation for details

----------------------------------------------------
BACKWARD COMPATIBILITY
----------------------------------------------------

All existing poll endpoints remain fully functional:
- Polls created without context field work normally
- Context field returns null for polls without context
- All voting, results, and management endpoints unchanged
- No breaking changes to existing integrations
