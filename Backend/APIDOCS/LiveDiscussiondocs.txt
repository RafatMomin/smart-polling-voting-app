Live Discussion REST API Reference
===================================

Summary
-------
The Live Discussion REST API allows users to create, manage, and participate in real-time discussions.
Discussions can be poll-specific (one-to-many: one poll, many participants) or general discussions
(many-to-many: multiple topics, multiple participants). Users connect via WebSocket for real-time
messaging and use REST API for discussion management.

Features
- Create poll-specific discussions (tied to a poll ID)
- Create general discussions (independent of polls)
- Join and leave discussions
- View discussion history and participants
- Real-time messaging via WebSocket
- Direct messages within discussions
- Discussion moderation (close/delete)
- Automatic cleanup of inactive discussions

Base Path: /discussions

----------------------------------------------------
1. Create Poll Discussion
POST /discussions/poll/{pollId}

Path Parameters:
- pollId (Long, required): The ID of the poll

Headers:
Authorization: {authToken}

Request Body (JSON):
{
  "title": "Let's discuss Poll #25 results",
  "description": "Open discussion about the campus food preferences poll. Share your thoughts on why certain options are winning!"
}

Response (JSON):
{
  "id": 1,
  "title": "Let's discuss Poll #25 results",
  "description": "Open discussion about the campus food preferences poll. Share your thoughts on why certain options are winning!",
  "type": "POLL_DISCUSSION",
  "pollId": 25,
  "hostUser": {
    "emailId": "user@example.com",
    "name": "John Doe"
  },
  "createdAt": "2025-11-04T14:30:00",
  "active": true,
  "participantCount": 1,
  "messageCount": 0,
  "websocketEndpoint": "ws://localhost:8080/discussion/1"
}

Error Responses:
{ "error": "Poll not found" }
{ "error": "Invalid token" }
{ "error": "Discussion already exists for this poll" }

DATABASE SCHEMA
----------------------------------------------------

Discussion Entity:
- id (Long, Primary Key)
- title (String, NOT NULL)
- description (TEXT)
- type (Enum: POLL_DISCUSSION, GENERAL_DISCUSSION)
- pollId (Long, Foreign Key to Poll, nullable)
- hostUserId (String, Foreign Key to Users)
- createdAt (LocalDateTime)
- closedAt (LocalDateTime, nullable)
- active (Boolean, default true)
- tags (List<String>, for general discussions)

DiscussionParticipant Entity (Join Table):
- id (Long, Primary Key)
- discussionId (Long, Foreign Key)
- userEmail (String, Foreign Key)
- joinedAt (LocalDateTime)
- leftAt (LocalDateTime, nullable)
- isHost (Boolean)
- lastSeen (LocalDateTime)

DiscussionMessage Entity:
- id (Long, Primary Key)
- discussionId (Long, Foreign Key)
- senderEmail (String, Foreign Key)
- content (TEXT)
- messageType (Enum: BROADCAST, DIRECT_MESSAGE, SYSTEM)
- recipientEmail (String, nullable, for DMs)
- timestamp (LocalDateTime)
- edited (Boolean, default false)
- editedAt (LocalDateTime, nullable)

Relationships:
- Discussion → Poll (Many-to-One, optional)
- Discussion → User (Many-to-One, host)
- Discussion ↔ User (Many-to-Many via DiscussionParticipant)
- DiscussionMessage → Discussion (Many-to-One)
- DiscussionMessage → User (Many-to-One, sender)

----------------------------------------------------
TECHNICAL NOTES
----------------------------------------------------

Authentication:
- All REST endpoints (except GET all discussions) require authentication
- WebSocket connections require token in query parameter
- Token validated on connection and stored for message attribution

Message Persistence:
- All messages stored in database for history retrieval
- WebSocket provides real-time delivery
- REST API provides historical message access

Auto-cleanup:
- Discussions inactive for 30 days automatically closed
- Participants marked offline after 5 minutes of inactivity
- System messages generated for joins/leaves

Performance:
- Message pagination with cursor-based approach
- Participant list cached in memory for active discussions
- WebSocket broadcast uses efficient session management

Limitations:
- Maximum 100 participants per discussion (configurable)
- Message content limited to 2000 characters
- DMs only within discussion context (not global)
- Discussion titles limited to 200 characters
